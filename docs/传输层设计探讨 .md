# 传输层设计探讨

## 场景规划

当前面向**有线局域网场景**（≤20台树莓派），采用**纯P2P架构**：通过mDNS实现初始节点发现，每个节点维护**全局路由表**（字典存储所有节点ID与IP映射），应用层通过**遍历广播**（O(N)）分发任务，节点间使用**RPC协议**（TCP 8888端口）传输控制命令，**HTTP服务**（9000端口）传输模型权重与数据。该方案**无中心Broker**，代码简洁（150行），延迟可接受（20节点广播约100ms），完全依赖底层交换机自动路由，无需额外网络协议。

未来面向**无人机集群等无线自组网场景**（节点移动、拓扑动态变化），可**无缝升级**为**洪泛广播+邻居表**架构：引入**BATMAN-adv**作为物理路由层，提供IP可达性与邻居发现，应用层切换为**FloodingRouter**，仅维护**1跳邻居表**，通过**TTL受限的洪泛**（邻居转发）实现消息传播，状态维护交由BATMAN内核协议，应用层代码仅需调整`get_neighbors()`实现，整体改动约50行。升级后系统兼具有线场景的高效与无线场景的动态适应能力。

## 网络层方法设计总结（MVP阶段）

基于分布式LLM推理场景需求，网络层 `Node.rs` 需实现以下12个方法：

### 方法列表

| 方法 | 输入 | 功能 |
|------|------|------|
| `Init(config)` | config配置 | 生成节点身份、初始化传输层/加密/多路复用、创建Swarm、初始化DHT |
| `Start()` | 无 | 启动监听，进入事件循环（处理节点发现/离开/连接/断开等） |
| `Stop()` | 无 | 停止网络，清理资源 |
| `Send_Command(peer, cmd)` | peer节点ID, cmd命令 | 发送命令给指定节点 |
| `Send_File(peer, path)` | peer节点ID, path文件路径 | 向目标节点发送文件 |
| `Send_Tensor(peer, tensor, request_id)` | peer节点ID, tensor张量, request_id | **流水线并行核心**：发送激活值张量 |
| `Put_Record(key, value)` | key键, value值 | DHT写入（节点能力声明等） |
| `Get_Record(key)` | key键 | DHT读取 |
| `Get_Peers()` | 无 | 获取当前已连接的所有节点列表 |
| `Get_Peer_Info(peer_id)` | peer_id节点ID | 获取特定节点详情（延迟、带宽、负载） |
| `Dial(addr)` | addr地址 | 主动连接到指定地址的节点 |
| `Disconnect(peer)` | peer节点ID | 主动断开与某节点的连接 |

### 功能覆盖

```
节点发现 ──→ DHT读写 ──→ 张量传输 ──→ 节点管理
    │           │           │           │
  mDNS/DHT   Put/Get    Send_Tensor   Get_Peers
  (Start)    Record                   Get_Peer_Info
                                      Dial/Disconnect
```

### 分类说明

**生命周期管理**
- `Init()` - 初始化
- `Start()` - 启动
- `Stop()` - 停止

**数据传输**
- `Send_Command()` - 控制命令
- `Send_File()` - 文件传输
- `Send_Tensor()` - 张量传输（推理核心）

**DHT操作**
- `Put_Record()` - 写入
- `Get_Record()` - 读取

**节点管理**
- `Get_Peers()` - 节点列表
- `Get_Peer_Info()` - 节点详情
- `Dial()` - 主动连接
- `Disconnect()` - 断开连接

### 备注

- `Get_Peer_Info()` MVP阶段至少需返回延迟信息，用于路径选择
- 事件订阅等监控功能在 `Start()` 事件循环内部处理，不单独暴露
