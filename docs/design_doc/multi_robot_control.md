# 多车协同控制设计（Multi-Robot Control）

> 创建日期：2026-08-10
> 状态：设计中（方案已讨论收敛，待实施）
> 范围：任务分配、散布形态、围堵、多车避碰、三层模型

## 1. 背景与目标

### 1.1 背景

单车阶段已闭环（SLAM / D* Lite / 走停控制 / gossipsub 广播）。向多车集群演进后，需要解决三类问题：

1. **任务分配**：给集群下达目标后，每辆车去哪、怎么散布
2. **协同行动**：多车同时行进，如何互不干扰（规避/让行）
3. **环境一致性**：地图同步、动态障碍与静态地图的区分

### 1.2 目标

1. 支持集群级命令（Goto / 围堵），每车**分布式自算**目标位置
2. 多车行进中安全规避（不碰撞、不死锁）
3. 车作为"动态障碍"参与路径规划，但**不污染静态地图**

### 1.3 非目标（第一版不做）

- 编队行进（leader-follower / 虚拟结构）——点对点任务不需要，留作后续
- 连续速度控制避碰（ORCA/势场）——执行层只有走/停，不适用
- 中心化调度（Kiva 式）——无中心约束
- 时间同步 / 跨车时钟（`now_boot_ms` 语义保持本机单调）

## 3. 总体架构：三层模型

```
┌─────────────────────────────────────────────┐
│ 意图层（终端/Pictor）：下发任务意图           │
│   目标点 / 命令类型 / 形态 / members 列表     │
├─────────────────────────────────────────────┤
│ 分配层（每车自算）：谁去哪个位置              │
│   peer_id 排序得序号 → 形态模板取位置         │
├─────────────────────────────────────────────┤
│ 执行层（每车）：导航 + 规避                  │
│   D* Lite（静态+动态障碍）→ 走/停 → 让行      │
└─────────────────────────────────────────────┘
```

**数据面分层**（地图/感知）：

```
┌─────────────────────────────────────────────┐
│ 静态层：SLAM 地图（墙/永久障碍）              │
│   ← LiDAR 点云（过滤"已知车"点）写入          │
├─────────────────────────────────────────────┤
│ 动态层：其他车位姿（gossip 10Hz 实时）        │
│   ← 用于：点云过滤 + 规划动态障碍 + 让行决策   │
├─────────────────────────────────────────────┤
│ 执行层：Executor（走/停 + 让行闸门）          │
└─────────────────────────────────────────────┘
```

## 4. 任务分配与散布形态

### 4.1 命令格式（概念层）

```
任务消息 = {
  命令: Goto | 围堵,
  目标点: (x, y),
  形态: 棋盘 | 环形,
  members: [peer_id...],        // 参与车辆（Pictor 选中生成）
  可选参数: { 半径, 间距 }       // 围堵用半径，Goto 用间距
}
```

- **广播**（gossip task topic），每车自过滤：不在 `members` 里 → 忽略
- **members 快照**：保证所有参与车对"成员列表 + 排序"一致，中途加入/离开不影响老任务

### 4.2 每车目标位置计算（确定性分配）

```
每车独立计算（零通信、零协商）：

1. 确定序号：members 按 peer_id 排序 → 自己的序号 i
2. 生成位置列表：形态模板按固定规则枚举（棋盘按 gx→gy 升序；环形按角度 0→2π）
3. 对号入座：我的目标 = 位置列表[i]
```

**确定性保证**：所有车对"members 排序"和"位置枚举顺序"用同一规则 → 结果全局一致，不会两车抢同一点。

### 4.3 散布形态

| 命令 | 形态模板 | 说明 |
|---|---|---|
| **Goto** | **棋盘同色格**：所有车放在 `(gx+gy)%2==0` 的格子上 | 前后左右空一格、斜对角有车；紧凑占领 |
| **围堵** | **环形均匀分布**：角度 θ=i/N·2π，目标=圆心+半径偏移 | 角度均分防空隙；第一版到达即停，不做朝向旋转 |

### 4.4 围堵的后续设计点（未定，留待后续）

- 半径参数来源（固定 / 按车数兜底 / 任务指定）
- 动态跟随（目标移动 → 圆心移动 → 圈平移）
- 朝向圆心（第一版不做）

## 5. 多车避碰

### 5.1 核心决策流程（规避状态机）

```
        ┌────────────────────────────────────────────┐
        │  NORMAL（行进）                             │
        │  动态层 10Hz 更新 / 路径有效性 500ms 校验     │
        └──────┬─────────────────────────────────────┘
               │ 冲突检测：与对方时空占用交集（预测 5s 窗口）
               ▼
        ┌────────────────────────────────────────────┐
        │  DECIDING（决策，≤200ms）                   │
        │  ① D* Lite 重规划（对方位姿注入动态障碍）    │
        │  ② 成功且代价比 ≤ 1.3 且通道够 → DETOUR     │
        │  ③ 否则 → 优先级比较 → 让行/继续            │
        └──────┬──────────────────────┬──────────────┘
               ▼                      ▼
        ┌───────────────┐      ┌──────────────────────┐
        │  DETOUR       │      │  WAIT（Stop）        │
        │  Forward 沿新  │      │  对方让出冲突区→NORMAL│
        │  路径（1Hz 节流│      │  超时 5s→ESCALATE    │
        │  重校验）      │      └──────────┬───────────┘
        └───────────────┘                 ▼
        ┌────────────────────────────────────────────┐
        │  ESCALATE（僵持升级）                       │
        │  广播 waiting_for → 等待图检测环            │
        │  优先级 aging（防饿死）                    │
        │  总超时 15s → 任务失败/上报                 │
        └────────────────────────────────────────────┘
        任意状态 ←—— EMERGENCY_STOP（LiDAR 兜底，3 帧去抖）
```

### 5.2 关键机制

| 机制 | 内容 | 出处 |
|---|---|---|
| **意图广播** | 位姿广播附带"下一格/前方 k 格"（第一版：下一格；后续扩展 k 格 + 时间窗） | Silver 2005 |
| **冲突检测** | **连续几何**（圆-圆/圆-线段扫掠 + 时间窗），不用"车在哪个格" | Open-RMF |
| **优先级** | `(ETA@冲突点, robot_id)` 字典序，小者先；**永不双向让**（根治互让死锁） | FCFS（Dresner & Stone 2008） |
| **绕行判定** | 重规划失败 / 代价比>1.3 / 通道不足 → WAIT，否则 DETOUR | nav2 工程惯例 |
| **绕行实现** | **D* Lite 重算**——动态障碍作为额外障碍集合传入，**规划器本体零改动** | D* Lite（增量重规划） |
| **重规划节流** | 动态层 10Hz 更新（廉价）与重规划 1Hz 节流（昂贵）解耦 | nav2 默认行为树 |
| **僵持检测** | 无进展计时器 + 等待图（gossip 广播 waiting_for） | CMH 1983；nav2 ProgressChecker |
| **兜底** | LiDAR 急停（现有）+ 去抖（连续 3 帧） | nav2 Collision Monitor |

### 5.3 参数清单（建议初值）

| 参数 | 建议值 |
|---|---|
| 动态层更新率 | 10Hz（随位姿广播） |
| 路径校验周期 | 500ms |
| 重规划节流 | 1Hz 最小间隔 |
| 冲突预测窗口 H | 5s |
| 绕行代价比 K | 1.3（可调 1.2-1.5） |
| 等待超时 T_wait | 5s |
| 僵持总超时 T_total | 15s |
| LiDAR 去抖 | trigger=3 / release=3 |
| 车车间安全距离 | 2r + 通信余量(0.1m) + 定位误差(0.05-0.1m) ≈ 0.75-0.8m（按实际车尺寸调整） |

## 6. 车与静态障碍的区分（三层模型的关键）

### 6.1 问题

- 雷达扫到车 → 若写入地图 → **幽灵障碍**（车走后残留）
- 规划若不考虑车 → 路径穿过停着的车

### 6.2 方案：点云过滤 + 动态层

```
LiDAR 点云 → 过滤层（点落在"已知车 footprint"内 → 丢弃）
           → 其余点 → SLAM 建图（静态地图）

广播中的车 = 动态对象（过滤，不进地图）
广播消失的车（断电/超时）= 静态障碍（重新进地图）→ 其他车绕行
```

**雷达物理特性**（2026-08-10 讨论）：激光雷达是车最高处，2D 平面可能扫不到车体（只可能扫到对面雷达）。**过滤参数（半径）待实车实测决定**：扫得到雷达 → 过滤半径≈雷达底座；完全扫不到 → 过滤可跳过，但必须做"通信超时保护"（0.5s 未收到位姿 → 视为未知 → 保守停车/绕行）。

### 6.3 规划中的动态障碍

```
D* Lite 重规划时：
  cost(格子) = 静态地图障碍 ∪ 其他车当前占用格（1-4 格，保守标记）
  → 规划器代码零改动，只是障碍集合多了动态部分
  → 车走后动态障碍自动移除，路径自动恢复
```

**横跨格子的处理**：车横跨 2-4 格时全标为障碍——保守安全（相当于自动膨胀）；正常行进中不会停在跨格位置，属于暂时状态；横跨堵死窄通道 → 绕行失败 → 等待（符合物理现实）。

## 7. 实施路线（建议顺序）

| 阶段 | 内容 | 依赖 |
|---|---|---|
| **P1** | 任务消息协议（命令/目标/形态/members）+ 确定性分配（序号+形态取位） | gossip task topic |
| **P2** | Goto 棋盘散布 + 围堵环形散布（第一版：到达即停） | P1 |

| **P6** | 僵持协商（waiting_for 等待图 + aging）+ 超时上报 | P4 |
