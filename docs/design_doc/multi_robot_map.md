# 多车分布式地图一致性（Multi-Robot Map Consistency）

> 创建日期：2026-08-11
> 状态：问题定义与现有方案调研（具体方案待讨论）
> 范围：多车共享同一张地图的一致性机制
> 关联：`docs/design_doc/multi_robot_control.md`、`Task/task_13_2_crdt_map.md`、`调研报告_分布式地图一致性方案.md`、`调研报告_增量补充_多机地图CRDT同步.md`

## 1. 我们要解决什么问题

### 1.1 问题陈述

多车集群（≤10 台）+ 控制终端，需要**持有同一张世界地图**：

- 每辆车通过自己的传感器（LiDAR/IMU）持续观测环境，更新本地地图
- 多车共同构建的是**同一片物理环境**，因此各车的地图本质上是"同一张地图的不同副本"
- 控制终端（地面站/WebSocket 客户端）需要查看这张地图，并基于地图坐标下达命令

**核心问题：如何让所有副本（各车 + 终端）最终收敛到同一份地图状态？**

### 1.2 为什么这个问题重要

地图一致是**命令语义成立的前提**：

- 终端下达"去坐标 (x, y)"——该坐标在地图上有意义，前提是终端看到的地图与车上的地图是同一张
- 若两车对同一区域的地图认知不一致（例如 A 认为某格是障碍、B 认为可行走），协同任务（分工探索、围堵、让行）会基于矛盾的世界模型执行，导致错误行为
- 车与车之间若不共享地图，就无法互相感知"对方看到了什么"——多车协作的认知基础缺失

### 1.3 问题定位

这是一个**分布式系统的多副本一致性（multi-replica consistency）问题**，而非 SLAM 算法问题：

- **被复制的数据**：一张 256×256 的 2D occupancy grid（log-odds 表示，i8 有界）
- **副本**：每辆车 + 控制终端
- **写者**：每辆车（各自传感器观测写入自己的副本）——多主（multi-master），无中央协调器
- **一致性目标**：最终一致（eventual consistency）——所有副本最终收敛到同一状态，允许中间短暂不一致

> 关键推论：一旦将问题定性为"多副本一致性"，分布式系统领域的成熟理论（可交换合并、gossip 传播、反熵对账）即可直接套用，无需发明新机制。真正的创新点在于**"把地图当作可复制数据"这一决策本身**（见 §3.4）。

### 1.4 环境与前提假设

| 前提 | 说明 | 现状 |
|---|---|---|
| 坐标系 | 多车共享同一坐标系（IMU 积分 + RTK 修正）；20min 漂移 < 1 格（0.5m） | ✅ 已实测验证 |
| 网格分辨率 | 0.5m/格，坐标误差在半格内被网格量化吸收 | ✅ 与漂移匹配 |
| 通信 | libp2p gossipsub 广播（best-effort，无 ack/重传） | ✅ 已有 |
| 地图表示 | 概率栅格，log-odds 有界 clamp ±8（阈值 ±6 派生三态） | ✅ 已有 |

### 1.5 非目标（本问题范围外）

- 多机回环检测 / 位姿图优化（坐标系对齐）——由 RTK/IMU 定位解决，不是本问题的内容
- 动态障碍物管理——动态障碍与静态地图分离，不进共享图（另行设计）
- 强一致（linearizable）/ 实时一致——无中央协调器场景不适用，也不需要
- 跨车时钟同步——各车 `now_boot_ms` 保持本机单调，不跨车可比

## 2. 现有方案全景

调研结论：**"分布式复制同一张栅格地图"在学术界是空白，工业界是中心化，学术界主流是"共享位姿而非共享地图"。** 按两个维度分类：谁持有地图（中心化 vs 分布式）+ 分布式时共享什么（网格 / 位姿约束 / 观测数据）。

### 2.1 方案分类表

| 模式 | 代表 | 全局地图？ | 中央节点？ | 坐标对齐方式 |
|---|---|---|---|---|
| **中心化网格** | 仓储 AMR（Kiva/Geek+）、矿山调度（DISPATCH）、CCM-SLAM、COVINS | ✅ 有（中央唯一权威） | ✅ 有 | 部署时统一建图/先验地图 |
| **中心化观测** | m-explore map_merge、NODE.maps | ✅ 有（中央合并后下发） | ✅ 有 | 各车发图给中心，中心对齐合并 |
| **分布式位姿图** ⭐学术主流 | Kimera-Multi、DOOR-SLAM、Swarm-SLAM、DCL-SLAM | ❌ 无（各车本地图） | ❌ 无 | **机间回环检测 + 分布式 PGO** |
| **分布式网格** ⭐我们的方向 | mrgs（2014）、stigmergic SLAM（2026）、Terrain-aware（DARPA SubT） | ✅ 有（各车持副本，复制收敛） | ❌ 无 | 各方案不同（见 2.3） |

### 2.2 中心化方案（工业主流）

**代表**：仓储 AMR、矿山无人卡车、清扫车队、CCM-SLAM、COVINS。

- 中央服务器/FMS 持有**唯一权威地图**，各车运行中上报更新，中央合并后下发
- 工业界选择中心化的原因：
  - 有基础设施（WiFi + 服务器）
  - **责任边界清晰**——"地图谁说了算"在产品合同里要明确，中央模式天然回答
  - 地图被视为"资产"，由中央管理

**局限**：单点故障、依赖基础设施、无法用于无中心/间歇连通场景。

### 2.3 分布式位姿图方案（学术界主流）

**代表**：Kimera-Multi（MIT, T-RO 2022）、DOOR-SLAM、Swarm-SLAM、DCL-SLAM。

工作机制：

1. 每车本地建图（各自持有本地地图副本）
2. 车间**不交换地图**，只交换紧凑描述子 + 关键帧，用于**机间回环检测**
3. 找到回环后做**分布式位姿图优化（PGO）**，把所有车的轨迹对齐到公共坐标系
4. 各车用纠正后的轨迹**各自修正本地地图**（mesh deformation）

**关键局限：没有重叠观测就没有回环约束，就没有全局地图。**

```
A 车在房间 101，B 车在房间 102，从未见过同一片区域
→ 无回环约束 → 两车轨迹无关联 → 地图是两个独立世界
→ 站在终端角度，拿不到一张完整的世界地图
```

这是学术方案的**固有边界**：它们的坐标桥梁是"见过同一面墙"（回环检测），非重叠区域物理上无法拼图。因此学术实验全部是多车**重叠探索同一环境**。

### 2.4 分布式网格方案（与我们同路，但极少）

| 项目 | 年份 | 关键机制 | 成熟度 |
|---|---|---|---|
| **mrgs**（gondsm/mrgs） | 2014 | 每车本地融合 + 增量融合树 + LZ4 压缩，跨 ROS master 收发 | M.Sc. 级，unstable，25★ |
| **stigmergic SLAM**（Triet & Thinh） | 2026 | 有界计数器 + 幂等瓦片合并，时变连通下有收敛证明 | 学术（微机器人 swarm） |
| **Terrain-aware mapping**（Team MARBLE，DARPA SubT） | 2021 | occupancy+traversability 编码进栅格，带宽约束下分发全车队 | 实战验证（SubT 第三） |
| **m-explore map_merge**（ROBOTICS 社区） | 活跃 | 双 topic（全量+增量），融合用 `cv::max`（单调幂等合并，非 log-odds 加法） | 开源活跃，但**中心化** merge 节点 |

**与我们的差异**：mrgs 没有坐标先验（需要对齐）；stigmergic 是单调计数器（无双向更新）；m-explore 是中心化。**没有现成项目同时具备：坐标先验 + gossipsub + 有界双向 log-odds + 无中央。**

### 2.5 工业界定位层 P2P 共享（近邻案例）

**SYNAOS**（VDA 5050 生态，2025）——三层地图模型：

| 层 | 内容 | 管理方式 |
|---|---|---|
| 定位层 | SLAM 图（栅格） | **车间 P2P 共享**——车检测到环境变化即与车队共享，中央 FMS 不介入 |
| 导航层 | 节点/边拓扑 | 中央管理 |
| 集成层 | 元模型 | 中央管理 |

**启示**：工业界验证了"定位层（栅格图）车间 P2P 共享"是真实产品模式；但工业整体仍偏中心化（地图=资产，责任清晰），P2P 复制仅限定位层。

## 3. 关键洞察（为什么我们的方向有空位）

### 3.1 坐标桥梁的两种来源

| 方案 | 坐标桥梁 | 是否需要观测重叠 |
|---|---|---|
| 学术界（回环） | "见过同一面墙"（回环检测 + PGO） | ✅ 需要 |
| 我们（坐标先验） | "见过同一个坐标系"（RTK/IMU） | ❌ 不需要 |

### 3.2 为什么学术界不做网格复制

多机 SLAM 圈的共识：**"网格复制在回环/位姿纠正面前很脆弱"**——位姿纠正后旧增量在新坐标系下无意义。该共识默认"SLAM 必须有位姿纠正"，于是直接排除了网格复制方向。**我们因为坐标先验（无需位姿纠正），恰好绕开了这个排除条件。**

### 3.3 为什么工业界不做 P2P 复制

有基础设施 + 责任边界需求 → 中心化是理性选择。**"无基础设施 + 需要全局地图"** 的组合在工业界是小众需求。

### 3.4 生态位结论

三个条件同时满足的场景此前不存在：

1. 坐标先验可用（低成本高精度 RTK/IMU 近年才普及）
2. 无中央基础设施需求（自组网）
3. 无需回环/位姿纠正（坐标先验足够稳）

我们的方案占据的是：**"分布式 + 全局地图 + 无中央"三者同时成立**的生态位——学术界（分布式无全局图）与工业界（中心化有全局图）之间的空档。创新点不在机制（增量广播、饱和吸收、log-odds 融合各有先例），而在**"以坐标先验替代回环检测，把地图当作可复制数据"的组合决策**。

## 4. 参考调研结论速览

### 4.1 分布式系统理论（可直接套用）

| 理论 | 内容 | 对本问题的意义 |
|---|---|---|
| **δ-CRDT**（Baquero 2018） | delta 传播 + 周期全量状态同步 ⇒ 强最终一致 | "增量广播 + 全量快照"的理论模板 |
| **PN-Counter 型 CRDT** | 按发送者单调累加 + 跨发送者加法合并 | log-odds 的"每发送者贡献隔离"结构 |
| **anti-entropy**（Demers 1987） | 纯 push 广播无送达保证，需周期对账 | "不做反熵"的代价边界 |
| **单调幂等合并**（max-consensus 等） | 有界单调操作对丢包/重复天然鲁棒 | 饱和吸收的理论支撑（限同方向） |

### 4.2 关键理论提醒（后续方案必须回答）

1. **逐次 clamp 破坏可交换性**：`log-odds 增量 + 每步 clamp` 不是交换操作，不同接收顺序可得到不同终值。要保证数学收敛，需按 CRDT 语义实现（per-sender 隔离 + 加法合并 + 读时 clamp）。
2. **纯广播不保证最终投递**：gossipsub 实测 ~10 节点即出现丢包（go-libp2p-pubsub #197）。丢包是"永久缺失"，饱和吸收只对持续观测的格子兜底。
3. **多车重复观测 = 过度自信**：各车对同一物体 +3 累加违反观测独立性。有界饱和天然限制上界（隐藏优点）。

### 4.3 调研发现的工程风险（后续方案需处理）

| 风险 | 说明 |
|---|---|
| gossipsub 丢包 | 小规模（~10 节点）实测存在，非理论 |
| 全量帧大小 | 65536B 接近 gossipsub 单消息上限（64KB），需压缩（RLE/LZ4）或分片 |
| msgid 内容哈希误用 | 不同车广播相同字节会被误判为同一消息，应用层需 (source, seqno) 语义 |
| 动态障碍 vs 幂等性 | 时间衰减破坏幂等；动态障碍建议不进共享图 |
| 观测重复计数 | 多车观测同一物体导致 log-odds 累加过快（饱和截断缓解） |

# 6. 我们的方案（讨论中，2026-08-11）

> 状态：方案讨论中，主干已定，部分细节待定。本文档记录当前讨论成果。

## 6.1 总体结构

```
每车维护：
  own（full map delta） — 本车观测累积贡献，i8，clamp ±8
  full map               — 当前合并地图，平时增量维护

平时（高频）：
  观测 → own += 观测(clamp ±8)；full map += 本车变化
  格子数值实际变化(Δ≠0) → 车对车广播增量 Δ = s_new − s_old
  收到增量 → full map += Δ

对账（低频，三方案候选见 6.4）：
  周期性把各车贡献合并成完整地图，替换 full map
```

核心语义：

- **广播的是变化值（Δ），不是观测量（绝对状态）**——接收方做加法，不重放
- **Δ≠0 才广播**：饱和格（±8）静默，带宽随时间衰减（地图越熟，广播越少）
- **状态翻转信息必然在变化过程中广播**（0→8 的若干次 +3/+2 不会被吞）
- **收敛靠对账兜底**：增量丢包造成的偏差，时间上界 = 对账周期

## 6.2 数值（沿用现状，grid.rs）

| 参数 | 值 | 说明 |
|---|---|---|
| 网格 | 256×256，0.5m/格 | 覆盖 128m×128m |
| 增量 | 命中 +3 / 掠过 −1 | 不对称 3:1（一次命中抵三次掠过） |
| clamp | [−8, +8] | i8 存储 |
| 阈值 | >+6 Occupied，<−6 Free | 中间 Unknown |
| 判定 | 3 次命中 → Occupied；7 次掠过 → Free | 从 0 出发 |

- 多车观测同一物体 = 独立观测累加（2 车各 1 次 = 1 车 2 次），语义自洽
- clamp 与阈值间距 = 2：饱和格 2 次反向观测即回 Unknown（动态性较强，静态环境可接受）
- clamp ±8 有界 = 防多车重复计数过度自信

## 6.3 增量广播（map delta）

- 广播内容：每周期每格**实际差分** `Δ = s_new − s_old`（clamp 后），Δ≠0 才广播
- clamp 边界处 Δ 可能非 ±3（如 6→8 时 Δ=+2）——接收方应用差分 + clamp 仍精确重放发送方路径
- 接收方：`full map ← clamp(full map + Δ)`
- 丢包影响：状态翻转广播只传一次，丢包则接收方停在旧值（例：发送方 5→8，接收方仍 5 → Unknown vs 墙）——由对账修复

## 6.4 对账方案（三候选，未定案）

### 方案 A：槽式（per-sender 槽）

```
每车存 N 个槽（每发送方一个贡献表，i8 ±8）
平时：收到 B 的增量 → full map += Δ；B 槽 += Δ
对账：收到 B 的 own 广播 → 替换 B 槽 → full map = clamp(Σ 各槽)
```

- ✅ 完全分布式、无中心、无单点
- ✅ CRDT 语义最标准（槽内全序 + 跨槽加法 + 读时 clamp）
- ❌ 内存 N×64KB；收到增量需同步更新槽（否则对账重算回退）；多车时复杂度最高
- 结论：**多车必须存槽才能本地合并**，除非换拓扑（B/C）

### 方案 B：链式两圈

```
第一圈（汇总）：A → B → C → D → A，每跳 full += 自己的 own
  → 发起车 A 拿到完整地图 Σ 所有车 own
第二圈（分发）：A → B → C → D，完整地图原样传递，每车替换自己的 full map
```

- ✅ 无槽、无中心；带宽省（每车 1 发 1 收 64KB）
- ❌ 对账延迟 2N 跳；断链需容错（跳过/重试）；发起者需轮换或固定（单点）
- 要点：汇总圈语义 = 累加，分发圈语义 = 替换（两圈不可混）

### 方案 C：终端聚合

```
① 每车：own 整表 → 终端
② 终端：合并 = clamp(Σ 各车 own)
③ 终端：完整地图 → 所有车（替换 full map）
平时增量仍车对车广播（P2P）
```

- ✅ 实现最简（终端一个 Σ 函数）；对账延迟 2 跳；无环依赖；终端天然存在（WS 地面站）
- ✅ 终端持有全局视图，可校验一致性（答辩/论文加分点）
- ❌ 依赖终端在线（比赛场景可接受）；无中心纯粹性
- **已定案（2026-08-11）：方案 C**（终端聚合）为主选

### 对账三方案对比

| 维度 | A 槽式 | B 链式 | C 终端 |
|---|---|---|---|
| 对账延迟 | 1 跳(广播) | 2N 跳 | 2 跳 |
| 每车带宽/轮 | 收 N×64KB | 收 1×64KB | 收 1×64KB |
| 断链容错 | 无需 | 需要 | 无需 |
| 单点 | 无 | 发起者 | 终端 |
| 实现复杂度 | 高 | 中 | 低 |

## 6.5 与 D* 规划的交互（2026-08-11 提出，待决策）
