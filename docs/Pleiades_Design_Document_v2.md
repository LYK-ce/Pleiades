# Pleiades 设计文档 v2

## 概述

Pleiades 是一个为边缘设备集群设计的分布式推理运行时框架。该框架允许设备：
1. 自动发现彼此（无需中央服务器）
2. 自动协商任务分配
3. 动态适应设备加入/退出
4. 每个设备运行相同代码，角色由运行时动态决定
5. 决策只依赖本地视图，无全局锁

## 核心组件

### 1. 配置模块 (Config)
- **功能**: 管理应用程序配置，包括网络设置、日志级别、运行时参数等
- **核心文件**: `config.rs`, `identity.rs`
- **配置格式**: TOML
- **主要结构**:
  - `Pleiades_Config`: 顶层配置
  - `Network_Config`: 网络相关配置（心跳间隔、超时时间、清理间隔等）
  - `Log_Config`: 日志配置
  - `Runtime_Config`: 运行时配置

### 2. 网络模块 (Network)
- **功能**: 提供P2P网络通信能力，基于libp2p实现
- **核心文件**: `network_service.rs`, `node_handle.rs`
- **特性**:
  - 自动节点发现（通过mDNS和Kademlia DHT）
  - 多协议支持（数据协议、流协议、张量流协议）
  - 心跳机制（基于libp2p ping协议）
  - 带宽测试功能
  - 连接管理和故障处理

#### 网络协议栈
1. **数据协议** (`data_protocol.rs`): 用于控制命令和小数据传输
   - `DataType`枚举: `Ping`, `Pong`, `Command`, `File`, `BandwidthTest`
   - 支持请求-响应模式

2. **流协议** (`stream_protocol.rs`): 用于大文件传输
   - 分块传输
   - 断点续传支持

3. **张量流协议** (`tensor_stream_protocol.rs`): 专门为张量数据传输优化
   - 零拷贝传输
   - 流水线支持
   - 内存映射优化

### 3. 节点管理模块 (PeerManagement)
- **功能**: 管理连接的节点信息，提供节点状态跟踪和能力管理
- **核心文件**: `peer_info.rs`, `peer_manager.rs`, `peer_handle.rs`
- **主要结构**:
  - `PeerInfo`: 节点信息（ID、地址、状态、延迟、带宽、能力等）
  - `PeerManager`: 节点管理器（CRUD操作、状态更新）
  - `PeerHandle`: 节点句柄（线程安全的对外API）

#### 节点状态管理
- `PeerStatus`: `Connected`, `Busy`, `Connecting`, `Disconnected`
- 心跳更新: 通过`update_heartbeat`方法更新延迟和最后活跃时间
- 带宽测试: 通过`update_bandwidth`方法更新带宽信息
- 能力管理: 通过`update_capability`方法更新节点能力（GPU、内存等）

### 4. ML推理引擎模块 (ML_Engine)
- **功能**: 提供机器学习模型加载和推理能力
- **核心文件**: `ml_thread_engine.rs`, `gguf_model.rs`
- **特性**:
  - GGUF模型格式支持
  - 多线程推理
  - 模型缓存和共享
  - 张量序列化/反序列化

#### 模型支持
- 当前支持: Qwen系列模型
- 框架: 基于Candle（Rust机器学习框架）
- 硬件加速: 支持CUDA（通过feature flag控制）

### 5. 控制模块 (Control)
- **功能**: 协调各个模块，处理用户命令，管理任务流程
- **核心文件**: `control.rs`, `command.rs`
- **主要功能**:
  - 命令解析和处理
  - 任务调度
  - 事件分发
  - 状态管理

#### 命令系统
- `CLI_Command`: 用户命令枚举
- `NodeCommand`: 节点间命令
- 支持的命令: `Run`, `Stop`, `Status`, `DisplayPeer`, `UpdateInfo`等

### 6. TUI模块 (TUI)
- **功能**: 提供终端用户界面，用于监控和交互
- **核心文件**: `app.rs`, `command_panel.rs`, `log_panel.rs`
- **界面布局**:
  - 命令面板: 输入命令和显示输出
  - 日志面板: 显示系统日志
  - 网络面板: 显示网络状态
  - 任务面板: 显示任务进度

## 数据流示例

### 1. 节点发现和连接
```
1. 节点启动 → 加载配置 → 初始化网络服务
2. 网络服务启动mDNS和DHT发现 → 发现其他节点
3. 建立连接 → NetworkEvent::ConnectionEstablished
4. 控制层收到事件 → 创建PeerInfo → 添加到PeerManager
5. 启动心跳检测 → 定期发送ping → 更新延迟信息
```

### 2. 带宽测试流程
```
1. 用户输入"update-info"命令 → Control层处理
2. Control层调用NodeHandle::Update_Info()方法
3. Network层遍历所有节点 → 对每个节点执行带宽测试
4. 发送BandwidthTest消息(1M,10M,50M数据包) → 测量往返时间
5. 计算带宽(Mbps) → 更新PeerManager中的bandwidth_mbps字段
6. 返回测试结果 → 在命令面板显示
```

### 3. 分布式推理流程
```
1. 协调者节点收到"run"命令 → 解析任务参数
2. 通过PeerManager选择合适的工作节点 → 考虑延迟、带宽、GPU能力
3. 发送Pipeline_Flow命令 → 建立张量流连接
4. 工作节点加载模型 → 准备推理
5. 协调者发送张量数据 → 通过Tensor Stream协议传输
6. 工作节点执行推理 → 返回结果
7. 结果聚合 → 返回给用户
```

## 故障处理机制

### 1. 心跳超时处理
- 当ping超时时，将节点状态标记为`Disconnected`
- 发送UI事件通知用户
- 记录到problem.md供后续分析

### 2. 连接断开处理
- 网络层检测到连接断开 → 发送`ConnectionClosed`事件
- 控制层收到事件 → 从PeerManager中移除节点
- 更新UI显示

### 3. 带宽测试失败处理
- 单个节点测试失败不影响其他节点测试
- 错误信息记录到info日志
- 返回成功/失败统计信息

## 扩展性设计

### 1. 模块化架构
