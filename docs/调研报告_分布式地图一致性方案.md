# 多车分布式地图一致性方案 —— Web 调研报告

> 调研范围：多机器人地图合并/共享主流方法、Kimera-Multi 通信与合并机制、CRDT 用于 occupancy grid / log-odds 的先例、gossip 类广播下的地图传播策略、工业界无人车/无人机集群实际做法、以及对我们方案的验证与风险提醒。
> 说明：本报告所有结论均来自公开论文/项目网页检索，链接见文末参考文献。

---

## 0. 结论速览（TL;DR）

1. **没有发现"把 occupancy grid / log-odds 直接做成 CRDT"的现成论文**——这在学术上基本是空白。最接近的分布式系统侧形式化是 **δ-CRDT（delta state replication）**（增量传播 + 周期全量状态同步），以及 **MRDT（mergeable replicated data types，三路合并）**。
2. **我们方案在工程上有两个非常近似的先例**：
   - 2026 年发表的微机器人集群 stigmergic SLAM 论文（Triet & Thinh, *Int. J. Adv. Robot. Syst.*）：**有界计数器 + 幂等瓦片合并（带时变连通下的收敛保证）+ 只传变化行的增量编码**——与我们"log-odds 增量广播 + 有界饱和 + 最终一致"几乎一一对应；
   - 学术界/工业界最常用的 occupancy grid 融合公式本身就是 **log-odds 加法**（Birk & Carpin 2006；OctoMap；m-explore map_merge 的 combine_grids），这天然是一个"可交换合并"。
3. **Kimera-Multi 是最接近我们"分布式多机共享地图"场景的系统，但它并不是复制同一张网格**：每车本地建图，只通过 P2P 交换"紧凑描述子 + 关键帧"做回环检测，再分布式优化位姿图，最后用位姿纠正本地网格（mesh deformation）。它的一致性来自"共享位姿图"，而非"共享网格状态"。通信是**按需 rendezvous 的 UDP 点对点，不是 gossip 广播**。
4. **对我们方案最重要的一条理论提醒**：`log-odds 增量 + 逐次 clamp 饱和` **不是交换操作**（有界饱和会破坏可交换性，不同顺序得到不同终值，甚至不同宏观态）。要拿到数学上可证明的最终一致，必须按 **CRDT 语义**实现：按 (发送者, 序号) 去重、按发送者单调累加、跨发送者用加法合并、clamp 只发生在"读时/输出时"（或按发送者单调计数器 clamp），并**必须有周期全量快照（anti-entropy）来修复丢包**——纯 best-effort 广播本身不保证最终投递。
5. **最容易被忽略的系统级风险**：单车内 SLAM 回环/位姿纠正会让整张本地图（以及此前广播的所有 log-odds 增量）在新旧坐标系下全部失效；多车无共同坐标系时 cell 索引不可比；多车对同一物体重复观测会造成 log-odds 重复计数（过度自信）。

## 2. 重点关注

### 2.1 Kimera-Multi：机制细节

**定位**：MIT ACL / SPARK 实验室（Tian, Chang, How, Carlone），IEEE T-RO 2022（arXiv 2106.14386），ICRA 2021 系统版（arXiv 2011.04087）。官方称其为"首个完全分布式、只依赖本地 peer-to-peer 通信、能拒绝感知混淆造成的错误机间/机内回环、实时构建全局一致 metric-semantic 3D 网格"的多机系统。开源：github.com/MIT-SPARK/Kimera-Multi。

**工作流程（关键点）**：
1. **每车本地跑 Kimera-VIO + Kimera-Semantics**，得到本地轨迹估计和本地 3D 网格——**没有一个全局共享网格**；
2. **通信层**：车与车之间通过轻量 UDP 层（"Remote Topic Manager"，peer-to-peer）通信，**只在两车进入通信范围时发起 rendezvous 式的交互**（不是持续广播）；
3. **分布式前端（位置识别/机间回环）**：发起方把"自上次 rendezvous 以来的新关键帧的 **BoW 全局描述子**"发给对方做匹配；匹配上之后，才交换"选定的关键帧（含关键点+描述子）"做**几何验证**，得到机间回环。**绝不交换原始图像/点云/网格**；
4. **分布式后端（鲁棒 PGO）**：两阶段——(a) 用 **GNC（graduated non-convexity）** 估计机器人坐标系间的相对变换（此阶段无需迭代通信）；(b) 用基于 RBCD 求解器的**分布式 GNC** 做全位姿图优化，鲁棒拒绝错误回环；
5. **本地地图纠正**：每个机器人用优化后的轨迹做 **mesh deformation**（Kimera-PGMO）纠正本地网格的漂移。

**带宽数据（论文报告，Medfield 数据集）**：整个分布式管线约 **65.9 MB**（22.6 MB 位置识别 + 41.5 MB 几何验证 + 1.8 MB PGO）；如果中心化传原始图像需要 **2113 MB**。即通过"只交换描述子+关键帧"把带宽压了两个数量级。

**一致性保证方式**：不是"复制同一份地图状态"，而是**共享位姿约束**——所有车最终收敛到一致的全局轨迹估计，各自用该轨迹纠正本地网格。它对回环离群有鲁棒的拒绝（这是与纯 CRDT 复制最大的不同：**回环/数据关联错误必须靠几何验证+鲁棒优化解决，CRDT 复制本身无法解决**）。

**对我们场景的启示**：如果我们把"共享地图"定义为"共享同一份格子状态"，Kimera-Multi 的模式是"每车本地地图 + 共享位姿图 + 本地纠正"。它的"轻量描述子交换 → 按需关键帧 → 分布式优化"带宽控制思路，值得我们在"何时广播哪些格子"上借鉴；但它不做 gossip 广播复制。

### 2.2 CRDT / log-odds / occupancy grid 先例

**直接先例：没有。** 检索 "CRDT occupancy grid"、"CRDT SLAM"、"log-odds CRDT"、"conflict-free replicated map robotics" 等组合，**没有找到任何把 occupancy grid 或 log-odds 地图建模为 CRDT 的学术论文**。这是研究空白，也是我们方案的创新空间。

**相关但不完全相同的先例**：

| 相关工作 | 内容 | 与本方案的关系 |
|---|---|---|
| **δ-CRDT**（Baquero et al., *J. Parallel Distrib. Comput.* 2018，"Delta state replicated data types"） | 形式化"delta 传播 + 周期全量状态同步"：状态型 CRDT 只传增量（delta），周期性同步全量状态，保证强最终一致（SEC） | **这就是"增量广播 + 周期全量快照"的分布式系统理论模板** |
| **MRDT**（Kaki et al., OOPSLA 2019，"Mergeable replicated data types"） | 用"3-way merge（v1,v2,LCA）"处理不完全满足 CRDT 性质的数据类型（列表、映射、向量等） | 如果 log-odds 合并不满足 CRDT 公理，可以用 LCA（周期快照可充当 LCA 近似）做三路合并 |
| **G-Counter / PN-Counter / LWW-Register / MV-Register** | 标准 CRDT 原语 | log-odds 的"每发送者单调贡献 + 跨发送者求和"正是 **PN-Counter/Map<发送者,G-Counter>** 结构；LWW 需要时间戳（我们无全局时钟，**不适用**）；MV-Register 保留并发值集合（对格子不实用） |
| **CRDT-based knowledge synchronisation in an Internet of Robotics Things ecosystem for AAL**（Galeas et al., *CVIU* 2025） | 用 δ-CRDT + pub/sub 同步机器人共享知识（语义图/状态），用于环境辅助生活 | "机器人 + CRDT"最直接的学术先例，但同步对象是**知识图谱状态**而非占用网格 |
| **Lasp / delta 框架**（Meiklejohn & Van Roy） | 面向 IoT/边缘的 δ-CRDT 编程框架 | 证明 CRDT 可跑在嵌入式/边缘节点上 |
| **Zylos 等工业博客**（2026） | "CRDTs and Distributed State Synchronization for Multi-Agent AI Systems" | 非学术，但说明"多智能体共享状态用 CRDT"正在成为行业共识方向 |
| **经典 log-odds 融合**（Birk & Carpin 2006；OctoMap；combine_grids） | 多机地图融合 = 对齐后 **log-odds 加法** | 数学基础：加法是可交换幺半群，天然"可合并"；**但逐次 clamp 会破坏可交换性**（见 §4） |

**log-odds 能做成 CRDT 吗？——关键理论判断**：

- **不加 clamp 的 log-odds 加法**是交换 + 结合 + 幂等（对同一发送者同一序号的更新去重后）的可合并操作 → 是 CRDT 友好结构。
- **逐次 clamp（有界 i8）会破坏可交换性**：例如从 5 出发，序列 (+3, −1) → 8→7；序列 (−1, +3) → 4→7→… 结果不同；更极端地，从 5 出发，(+3,+3) 后 −1 → 8→7；(−1 先) 后 (+3,+3) → 4→7→… 也会不同。**最终数值取决于"是否在某一步先撞上边界"**。
- 因此"接收方用相同逻辑重放 + 有界饱和"要**数学上保证收敛**，需要改成 CRDT 语义：
  1. 每条增量带 **(发送者ID, 发送者内单调序号)**，接收方按此**去重**（解决 at-least-once 重复）；
  2. **按发送者分别单调累加**（每个发送者自己的贡献是一个单调计数器，序号有序保证确定性）；
  3. 跨发送者合并用**加法**（PN-Counter 式），**clamp 只发生在"读时/输出宏观态时"**（或对每个发送者单调计数器 clamp，即每个发送者自己的计数饱和后不再变）；
  4. 若按上述实现，收敛由"每条消息最终被每个副本收到"保证——而这一点**必须靠周期全量快照/anti-entropy**（见 §3）。
- **有界饱和的"抗丢包"论证（有理论支撑，但有前提）**：
  - 若更新是**单调**的（只增或只减），饱和边界是吸收态：已饱和的格子在边界方向的后续更新不改变存储值 → 丢包不影响终值。这正是 stigmergic 论文里"merge 设计为有界单调操作"的论证，也对应 max/min-consensus（幂等、对丢包/重复天然鲁棒）。
  - 但我们的 +3/−1 是**双向**更新：饱和边界对"反向更新"不是吸收的，所以"饱和抗丢包"只对"同方向溢出部分"成立，**不能作为最终一致的充分条件**。最终一致仍依赖"每条增量最终到达每个副本 + 去重 + 可交换合并"。

### 2.3 其他多机 SLAM 的"共享地图"范式

- **中心化**（CCM-SLAM / COVINS）：每车只做前端（里程计），把 keyframe 传给中心服务器，服务器持有并维护唯一全局图。优点是简单，缺点是有单点故障、需要回程带宽。
- **分布式共享位姿图**（Kimera-Multi / DOOR-SLAM / Swarm-SLAM / DCL-SLAM）：每车本地维护轨迹与本地地图；车间只交换"紧凑描述子/关键帧/回环约束"，用**分布式 PGO**把各车轨迹对齐到公共坐标系；本地地图随后被纠正。**没有任何一车持有全局网格副本，也没有网格复制**。
- **分布式复制网格（我们的路线）**：与上述都不一样——我们希望所有车持有**同一份网格状态**并通过复制收敛。这在学术 SLAM 文献里几乎无人做，但在**分布式系统领域**（CRDT/δ-CRDT/anti-entropy）有成熟理论，在**极简 swarm 建图**（stigmergic 论文、纳米无人机论文）有工程雏形。**这是我们可以明确的定位：把"地图一致性"从 SLAM 问题降维成"分布式复制数据结构问题"**，前提是坐标系已经对齐。

## 3. 广播协议（gossip 类）下的地图传播策略

### 3.1 Delta + 周期全量快照：不是优化，是**正确性必需**

- **形式化**：δ-CRDT 论文（Baquero et al. 2018）证明 delta 传播 + 周期全量状态同步可实现强最终一致。delta 负责低延迟传播，全量同步负责"修复漏投递"。
- **反熵（anti-entropy）**：源自 Demers et al. 1987（*Epidemic algorithms for replicated database maintenance*），工业实现如 **Cassandra（周期 gossip + 修复）**、**Consul（agent 周期与 catalog 对账）**、**Hyperledger Fabric gossip（每个 peer 从 channel 内其他 peer 拉取缺失块修复状态）**。核心是：**纯 push 广播 + 丢包不重传 ⇒ 必然丢更新 ⇒ 必须周期性 pull/push 全量状态（或摘要）来对账**。
- **对我们的意义**：gossipsub 是 best-effort、at-least-once、无 ack/重传。**仅靠增量广播无法保证最终一致**；周期全量快照（或"瓦片摘要/哈希广播 + 差异重传"）不是可选项，而是最终一致的**必要条件**。注意 gossipsub 只有 push；若想 pull，可以在 libp2p 上并行跑一个轻量 request/response 协议（libp2p 支持多协议并存），或退化为"周期性全量广播（分片轮播）"。

### 3.2 有界状态与抗丢包的理论支撑

- **单调 + 饱和**：max/min-consensus 类合并（Deplano et al., arXiv 2402.18719：有向图丢包下有限时间收敛的 max-consensus；以及 min-max 一致性文献）证明：**单调、幂等、有界**的合并对丢包与重复天然鲁棒（重复不影响结果，已饱和值的多余更新不影响结果）。
- **时变/间歇连通图的收敛**：经典共识理论——Jadbabaie, Lin & Morse 2003；Olfati-Saber & Murray 2004；Xiao & Boyd 2004；Boyd et al. 2006——证明在**反复连通的图上**（不要求同时全连通），局部交换/平均/一致性能收敛。stigmergic 论文正是引用这类结果："**交互图反复连通（B-connectivity）+ 扰动有界 ⇒ 局部、顺序无关的更新收敛**"，并把合并设计为**有界单调整数操作**。
- **结论**：我们"有界 log-odds + 增量重放"如果实现为"每发送者单调计数 + 跨发送者加法 + 读时 clamp + 周期快照修复"，就落在上述两个理论的支持范围内；如果实现为"逐次 clamp 的共享变量"，则**不受**上述理论支持（见 §4-1）。

### 3.3 带宽视角

- 只广播**状态发生变化的格子** + **行程编码（run-length）只传变化 runs**：微机器人 stigmergic 论文的 "proximal delta encoder" 和 m-explore、纳米无人机工作都验证了这一点；2D 栅格大块 Free/Unknown 连续区域压缩收益很高。
- gossip 广播存在 O(N) 放大：一条增量会被中继 N 次；需要**消息 ID 去重（gossipsub 内置）**、TTL/扇出控制、批量打包。

## 4. 对我们方案的验证与风险/遗漏提醒

### 4.1 方案本身：方向正确，但实现语义必须 CRDT 化

**支持的证据**：
- log-odds 加法是经典融合公式（Birk & Carpin；OctoMap；m-explore），"接收方重放增量"即"增量式 log-odds 融合"；
- δ-CRDT 给了"delta + 周期快照"的收敛证明框架；
- stigmergic 微机器人论文给出了"有界计数器 + 幂等合并 + 时变连通收敛"的工程先例；
- 从"广播宏观三态变化"改为"广播 log-odds 增量"是**明显进步**：宏观态变化事件（如 Unknown→Occupied）不携带"接收方该加多少"的信息，接收方本地值不同时无法据此收敛；而 log-odds 增量让接收方用同一融合逻辑重放，数学上更干净。

**必须补上的四个实现条件（否则"最终一致"不成立）**：
1. **去重**：每条增量带 (发送者ID, 序号)；接收方按此过滤 at-least-once 重复与网络层重复（gossipsub 消息 ID 也应编码这两个字段）。
2. **可交换合并**：不要"共享变量逐次 clamp"。改为按发送者单调累加、跨发送者加法求和、clamp 在读时/输出时进行（或对每发送者计数器 clamp）。
3. **周期全量快照/anti-entropy**：纯广播不保证最终投递；必须有周期性对账（全量快照广播、或瓦片摘要 + 差异重传、或 libp2p 上的 pull 通道）。
4. **坐标系共享/对齐前置**：见 4.2。

### 4.2 风险 / 遗漏清单（按严重度排序）

1. **单车内回环/位姿纠正会使"增量重放"整体失效（最容易被忽略）**。车自己 SLAM 回环闭合或位姿图优化后，本地整张栅格（所有 cell 的 log-odds）都要重投影/重算；此前按旧坐标系广播的增量在新坐标系下无意义，接收方重放后依然不一致。Kimera-Multi 的解法是"位姿优化后做 mesh deformation"；我们必须在设计里加入**地图版本化（map epoch）**：回环/位姿纠正后 bump epoch，后续广播携带 epoch，接收方对旧 epoch 的格子做"作废/覆盖"，必要时重新广播变化块。**这比"格子级 CRDT"更高一层，是必须处理的系统级问题。**
2. **多车坐标系不对齐 ⇒ cell 索引不可比**。所有经典 map merging 论文的第一大步骤都是"求相对变换/对齐"；如果各车 frame 不同（无 GPS/RTK/UWB 公共参考），gossip 的格子增量就是垃圾数据。要么前置"公共世界坐标系 + 已知初始相对位姿"，要么先做机间回环/注册（参考 Kimera-Multi 的 BoW+关键帧方案）再开 gossip 复制。
3. **有界饱和破坏可交换性（数学层面）**。如上 §2.2 所述，逐次 clamp 的 +3/−1 重放不是交换操作，不同顺序可产生不同终值甚至不同宏观态（给出阈值穿越的反例：cell 从 5 出发，两车并发 +3 与 −1，一车先加后减得 Occupied，另一车先减后加得 Unknown）。**必须按 CRDT 语义实现，否则"最终一致"只是假设。**
4. **重复计数（double counting）/ 过度自信**。多车观测同一面墙，每车都广播 +3，接收方 log-odds 相加违反"观测独立"假设 → 地图过度自信。缓解：饱和 clamp 天然限制上界（这是有界 log-odds 的一个隐藏优点），阈值附近仍可能不一致；工业实现（OctoMap 等）同样面对此问题，普遍接受饱和截断作为折中。
5. **动态障碍物**。延迟/乱序投递下，某格子的宏观态可能在 Free↔Occupied 间振荡（慢速反熵期）；Yguel 2007 的 clamping 策略表明**clamp 恰好保证地图"可更新"**（不会卡死在极端值），这支持我们用 clamp 而非无界计数，但要注意"新鲜度 vs 稳定性"的权衡，可考虑加时间衰减或指数遗忘（expiration），不过这会引入新的收敛性问题（需要小心设计，否则破坏幂等）。
6. **无全局时钟**：不要用 LWW-Register（时间戳不可比）；用 per-sender 单调序号 + 可交换合并。若确实需要"谁更新"语义，用 (发送者ID, 序号) 全序而非时间。
7. **带宽放大与初始快照成本**：gossip O(N) 放大；周期全量快照在网格大时昂贵。建议：快照用"瓦片级哈希摘要广播 + 有差异才传块"；增量用 run-length；gossipsub 扇出/TTL 限制。
8. **收敛语义要定义清楚**："一致"应是"最终每个副本都应用了每个（未过期的）更新"（或该更新已被饱和吸收），而不是"任意时刻一致"；要向团队明确这是**强最终一致（SEC）**而非实时一致，规划/避障层要容忍短暂不一致。
9. **广播"宏观态变化格子"方案的固有缺陷**（现在的方案）：除了信息量不足外，宏观态变化是"阈值穿越"事件，对重复/乱序更敏感（一个 +3 使 Unknown→Occupied，乱序后可能又变回去，产生抖动广播）。改 log-odds 增量可显著缓解。
10. **消息体大小/频率设计**：每车传感器更新率高（10Hz 激光），全量广播变化格子在集群规模大时可能打满链路；需要**批处理 + 节流 + 优先级（Nearby 格子优先）**。

### 4.3 业界/学界有没有"支持或反对"我们的案例

- **支持**：分布式系统界（δ-CRDT、anti-entropy、Cassandra/Fabric gossip）证明"gossip + delta + 周期全量对账 + 可交换合并 ⇒ 最终一致"是成熟范式；机器人界微机器人 stigmergic 论文与纳米无人机分布式建图证明了"低端设备上分布式栅格合并"可行。
- **不支持（或提醒）**：主流多机 SLAM（Kimera-Multi 等）刻意**不复制网格**，因为网格复制在"回环/位姿纠正/坐标系对齐"面前非常脆弱——它们选择"复制位姿约束 + 本地地图自纠"。我们的方案要在"地图复制"上做，就必须把 §4.2 的 1、2、3 解决掉，否则会踩进多机 SLAM 界早就绕开的坑。
- **工业界**：仓储/矿山全部是中心化地图管理（地图是"资产"，由中央下发），P2P 地图复制在工业落地极少见——一方面因为仓库有 WiFi+服务器，另一方面因为"地图谁说了算"在责任边界上更清晰。我们方案的卖点应定位在**无基础设施/间歇连通/自组网**场景。

## 附：给团队的一句话建议

把方案正式表述为：**"occupancy grid 作为按 cell 分解的、以 (发送者ID, 序号) 为主键的增量复制数据结构（PN-Counter 型 CRDT 的 2D 实现），通过 gossipsub 广播增量、以周期全量快照（anti-entropy）做对账，宏观三态在读取时由 clamp 后的 log-odds 阈值派生"**。这样每一环（去重、可交换合并、饱和、收敛条件）都有成熟理论背书，也便于评审与后续证明。同时**先解决"坐标系对齐"和"回环/位姿纠正后的地图版本化"两个前置问题**，否则格子级复制无从谈起。
